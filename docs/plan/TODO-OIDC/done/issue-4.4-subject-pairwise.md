# 4.4 — Subject pairwise

- **Fase:** 4 · **Estado:** implementada y verificada (27-10-2026), [J-13](../epicas/done/ep-J-13-solicitudes-claims-avanzados.md).
- **Implementación:** `SubjectResolver`: cliente `subject_type=PAIRWISE` → `HMAC-SHA256(oidc.pairwise.salt, sector | username)`; sector = host de `sector_identifier_uri` o el único host de sus redirects. Se aplica a ID token, **access token** (sin el claim `uid` global), UserInfo, introspección, logout token e `id_token_hint` (authorize y logout). El refresh token, que solo lee este servidor, conserva el username. UserInfo y token exchange obtienen el usuario local del registro del token (`TokenIntrospectionResult.localSubject`/`localUid`, nunca serializados), no del JWT; la introspección devuelve el `sub` del token. Un access token pairwise no sirve para la API de administración de phylax (su actor no es un usuario local): falla cerrado. Sin sal o sin sector único: falla cerrado. `pairwise` solo se anuncia con sal configurada.
- **Pendiente real:** configurar `OIDC_PAIRWISE_SALT` (no rotarla: cambiaría los `sub`); no se descarga ni valida el documento de `sector_identifier_uri` (clientes de administración).
- **Pruebas:** `PairwiseSubjectFlowTest` (ID, access sin `uid`, UserInfo e introspección con el mismo `sub` sectorial), `SubjectResolverUnitTest`.
