# A0.6 — Hash de contraseñas de usuario

- **Fase:** 0 · **Esfuerzo:** M–L · **Estado:** pendiente · **Dónde:** `common/security` + `user` + `oauth`.
- **Problema:** [PasswordVO.java:102-115](../../src/main/java/net/civeira/phylax/features/access/user/domain/valueobject/PasswordVO.java#L102-L115) cifra con `AesCipherService.encryptForAll` (una clave global, por defecto `eventual`), y el login descifra y compara con `equals` ([UserLoginService.java:250](../../src/main/java/net/civeira/phylax/features/oauth/user/infrastructure/UserLoginService.java#L250)). Si se tienen la base de datos y la clave, todas las contraseñas quedan en claro. Además `checkPassword` omite la comprobación cuando `password == null`.
- **Implementación:** Crear un puerto `PasswordHasher` (Argon2id o bcrypt) en `common/security`, con su adaptador en infraestructura. `PasswordVO` guarda solo el hash y expone `matches(raw, hasher)`; deja de depender de `AesCipherService` (lo que también resuelve la fuga dominio → CDI del análisis anterior). Migración: en cada login correcto, rehashear las contraseñas cifradas; de forma opcional, un batch que las rehashee todas, descifrándolas una sola vez. Rechazar `password == null`. La semilla TOTP sigue cifrada (tiene que ser reversible).
- **Cierre:** En la base de datos solo hay hashes con un prefijo de algoritmo. Los usuarios antiguos siguen pudiendo entrar y quedan migrados. Las contraseñas incorrectas o `null` se rechazan. La comparación no depende de `String.equals`. Coordinar con [2.9 de OIDC](../TODO-OIDC/done/issue-2.9-migracion-secretos-cifrado.md).
