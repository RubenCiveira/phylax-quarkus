= Calidad del código

[cols="1,2,2",options="header"]
|===
|Aspecto |Herramienta |Cómo
|Formato |Google Java Style con `formatter-maven-plugin`; orden de imports |Se aplica en cada build Maven, también al código generado
|Análisis estático |PMD y CPD (código duplicado) |`make lint`, que deja los resultados en `target/lint`
|Dependencias vulnerables |OWASP Dependency-Check |`make sast`. Con `NVD_API_KEY` la descarga de la base de vulnerabilidades es mucho más rápida
|Cobertura y mutación |JaCoCo, PIT |Ver <<cobertura-y-mutación>>
|===

Como el build reformatea el código, un `git stash` alrededor de una ejecución de Maven puede dejar conflictos de formato. Para probar otra revisión, mejor un _worktree_.

Revisión de un cambio:

* El código generado no se modifica a mano (ver <<generación-de-código>>).
* Toda regla nueva va acompañada de su prueba, incluido el camino denegado.
* Los cambios de contrato se hacen primero en el OpenAPI.
