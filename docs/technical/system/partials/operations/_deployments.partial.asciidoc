= Construcción y despliegue

== Artefactos

La aplicación se distribuye como imagen de contenedor. Los Dockerfiles están en `src/main/docker`:

[cols="2,3",options="header"]
|===
|Dockerfile |Uso
|`Dockerfile.native-micro.multistage` |*Imagen de referencia.* Compila el ejecutable nativo con Mandrel (JDK 25) y lo copia a `quarkus-micro-image`. `make docker-build`
|`Dockerfile.jvm.multistage` |Imagen JVM. `make docker-build-jvm`
|`Dockerfile.native`, `Dockerfile.native-micro`, `Dockerfile.jvm`, `Dockerfile.legacy-jar` |Variantes de Quarkus que empaquetan un build hecho fuera de Docker
|===

Para probar la imagen en local: `make docker-run`, con las variables de `src/main/docker/env.local/.env`.

[WARNING]
====
* `Dockerfile.jvm.multistage` compila con JDK 21, pero el proyecto requiere Java 25.
* Los Dockerfiles declaran `EXPOSE 8080`, pero la aplicación escucha en `APP_PORT` (`8090` por defecto).
====

== Integración continua

No hay un pipeline activo. `_x_nop_gitlab-ci.yml` contiene, comentado, el job que construía la imagen nativa y la publicaba en el registro de GitLab.

== Publicación de una versión

Siguiendo <<gitflow>>:

. `make start-rc` calcula la versión siguiente a partir de la de `main` y del tipo de los commits (mayor si hay un _breaking change_, menor si hay `feat`, parche en otro caso). Crea `release/x.y.z-rc.n` desde `develop`, ajusta la versión del `pom.xml`, añade la entrada al `CHANGELOG.md` y hace el commit `chore(release): x.y.z-rc.n`. La rama se publica a mano.
. La release candidate se despliega en staging y se valida. Las correcciones se hacen en la propia rama.
. Para la versión definitiva se crea `release/x.y.z` a mano, con la versión y el changelog ajustados.
. La rama se cierra con pull request contra `main` y `develop`. Se etiqueta `main` con `vX.Y.Z`.
. La imagen de producción se construye *desde la etiqueta*.

`make generate-changelog` reconstruye el `CHANGELOG.md` a partir de las etiquetas y los mensajes de commit; por eso los commits tienen que seguir <<conventional-commits>>.

NOTE: `CONTRIBUTING.md` menciona `make start-release` y `make finish-hotfix-*`, pero no existen. Hoy solo hay `start-feature-*`, `finish-feature-*`, `start-hotfix-*` y `start-rc`.
