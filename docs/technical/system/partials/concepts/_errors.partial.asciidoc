= Modelo de errores

El dominio y los casos de uso lanzan excepciones de `common/exception`. Los `ExceptionMapper` de `common/infrastructure/exceptionmapper` las traducen a HTTP en un único sitio: los controladores no capturan errores.

[cols="2,1,3",options="header"]
|===
|Excepción |HTTP |Cuándo
|`NotAllowedException` |401 / 403 |La autorización deniega: 401 si el actor es anónimo y 403 si no.
|`StepUpRequiredException` |401 |Hace falta un nivel de autenticación mayor (MFA). Incluye el reto en `WWW-Authenticate`.
|`NotFoundException` |404 |La entidad no existe o no es visible para el actor. No se distingue entre los dos casos, para no revelar su existencia (xref:{adr-root}/0004-respuestas-indistinguibles-ante-enumeracion.adoc[ADR-0004]).
|`OptimistLockException` |412 |La `version` enviada no coincide: alguien modificó la entidad antes.
|`ConstraintException` y demás `AbstractFailsException` |422 |Validaciones de un `Check` o de los value objects.
|`NotUniqueException` |422 |Clave única duplicada.
|`NotExistentReferenceException` |422 |Una referencia apunta a una entidad que no existe.
|`NotEmptyChildsException` |422 |Se intenta borrar una entidad que tiene hijos.
|`PaymentRequiredException` |402 |Requisito de pago o suscripción no cumplido. Hoy ningún caso de uso la lanza.
|`UncheckedIOException` |502 |Fallo de un sistema externo.
|`UncheckedSqlException`, cualquier otra |500 |Error no contemplado. Hoy se registra como `WARN`; según <<logging>> debería ser `ERROR`.
|===

Los errores de validación (422) se localizan con el idioma de `Accept-Language` (catálogos en `src/main/resources/messages`) y se agrupan por código de error.

ifdef::module-oauth[]
Los endpoints del protocolo OAuth no siguen este modelo: responden con los errores tipados de la especificación (`OAuthTokenException`), según se describe en xref:{docs-root}/technical/contexts/oauth/04-endpoint-token.adoc[Endpoint de token].
endif::[]

WARNING: Una violación de clave foránea que no detecta ninguna validación previa responde 500 en lugar de 409 (link:{docs-root}/plan/TODO/issue-A2.4-violacion-fk-409.md[A2.4]).
