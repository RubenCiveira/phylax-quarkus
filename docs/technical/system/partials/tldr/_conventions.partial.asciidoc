= Convenios en una página

Resumen de los convenios de xref:{adr-root}/0003-flujo-de-versionado-y-publicacion.adoc[ADR-0003], desarrollados en <<convenios-de-desarrollo>>.

Gitflow::
* `main` tiene el código de producción y `develop` el desarrollo estable. No se hacen commits directos sobre ninguna de las dos.
* Una rama `feature/<nombre>` por funcionalidad: sale de `develop` y vuelve a `develop`.
* Una rama `hotfix/<nombre>` por corrección urgente: sale de `main` y vuelve a `main` y `develop`.
* Una rama `release/x.y.z-rc.n` para validar una versión: sale de `develop` y se cierra con pull request contra `main` y `develop`.

Versionado (SemVer)::
* *Mayor*: cambios incompatibles. Es `0` hasta el primer paso a producción.
* *Menor*: funcionalidades nuevas compatibles.
* *Parche*: correcciones.
* Sufijo `-rc.n` para las release candidates y `-SNAPSHOT` en `develop` y en las features.

Mensajes de commit (Conventional Commits)::
+
----
<tipo>[(ámbito)]: <descripción>

[cuerpo]

[pie]
----
+
Tipos: `feat`, `fix`, `chore`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `revert`, `remove`.

Niveles de log::
* `ERROR`: el flujo falló por algo no contemplado. Debe generar una alerta.
* `WARN`: el flujo sigue, pero ocurrió algo inesperado que hay que revisar.
* `INFO`: los hitos principales del flujo.
* `DEBUG`: detalle para depurar, incluidos los valores de los objetos. Nunca secretos.
