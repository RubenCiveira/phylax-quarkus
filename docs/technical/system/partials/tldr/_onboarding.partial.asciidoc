= Onboarding

{project-name} es un proyecto Maven de un solo módulo que construye un backend Java sobre Quarkus, organizado en los paquetes `bootstrap`, `common` y `features` (ver <<arquitectura-del-código>>).
Expone una API REST (`/api/...`) cuyo contrato está en `src/main/resources/META-INF/openapi/api.yaml`.
ifdef::module-oauth[]
Incluye el módulo `oauth`: un servidor OAuth 2.0 / OpenID Connect multi-tenant (`/oauth/...`).
endif::[]

Para arrancarlo en local:

. Clonar el repositorio y ejecutar `make init`, que instala los hooks de Git (validación de conventional commits).
. Crear el fichero `.env` en la raíz con la conexión a la base de datos y los secretos. Ver <<configuración>>. El fichero no se versiona.
. Crear una base de datos MariaDB vacía con codificación UTF-8 y un usuario propio. Las migraciones se aplican solas al arrancar.
. Arrancar en modo desarrollo con `./mvnw quarkus:dev`. La aplicación escucha en el puerto `8090`.
. En el primer arranque, con la base de datos vacía, se cargan los datos iniciales de `src/main/resources/migration/seed/`.
ifdef::module-oauth[]
En este proyecto, `oidc-seed.yaml` crea el tenant raíz `main`, el usuario `ROOT` y los clientes iniciales. Si no se fijó `OIDC_ROOT_PASSWORD`, la contraseña temporal de `ROOT` aparece una sola vez en el log (ver xref:{docs-root}/operations/oauth/01-instalacion.adoc[Instalación]).
endif::[]

Comandos habituales:

[cols="1,3",options="header"]
|===
|Comando |Qué hace
|`./mvnw quarkus:dev` |Arranque en modo desarrollo con recarga en caliente
|`./mvnw generate-sources` |Regenera las interfaces REST a partir del contrato OpenAPI
|`./mvnw test` |Pruebas unitarias y de integración
|`./mvnw verify -Pcoverage` |Pruebas con informe de cobertura (JaCoCo)
|`./mvnw verify -Pmutation` |Pruebas de mutación (PIT)
|`make test-mariadb` |Pruebas de los adaptadores SQL contra MariaDB, en un esquema desechable
ifdef::module-oauth[]
|`src/test/conformance/run.sh` |OpenID Conformance Suite contra el servidor OIDC
endif::[]
|`make docker-build` |Imagen nativa (`Dockerfile.native-micro.multistage`)
|===

NOTE: `make format`, `make lint`, `make sast`, `make verify` y `make test` montan un `pom.xml` temporal con perfiles de `.ci/actions/conf/maven/`, que no está en el repositorio.
ifdef::module-oauth[]
Además, `make conformance` apunta a `./conformance/run.sh`, pero el script está en `src/test/conformance/`.
endif::[]
