= Arquitectura del código

La aplicación es un monolito modular. La clase de arranque está por encima de los contextos. `bootstrap` y `common` son transversales, y la funcionalidad se divide en *contextos* de dominio (`features/<contexto>`) con alta cohesión. Dentro de cada contexto, cada entidad sigue su propio diseño hexagonal.

La decisión y sus alternativas están en xref:{adr-root}/0002-monolito-modular-con-arquitectura-hexagonal.adoc[ADR-0002].

== Capas

.Arquitectura hexagonal de una entidad
[plantuml, "hexagonal", svg]
....
include::../../diagrams/hexagonal.puml[]
....

`domain`::
El agregado, sus value objects y sus eventos. Declara en `domain/gateway` los puertos que necesita: repositorio de lectura, repositorio de escritura, caché y auditoría. No depende de Quarkus ni de las otras capas.

`application`::
Un paquete por caso de uso (`usecase/<op>`), las reglas de visibilidad (`visibility`) y las políticas escritas a mano (`policy`). Los casos de uso son los puertos de entrada: los drivers los invocan directamente, sin interfaz intermedia.

`infrastructure`::
Los drivers (`driver/rest`, un controlador por caso de uso) y los adaptadores de los gateways (`driven`, `repository`, `event`).

Reglas de dependencia:

* `infrastructure` → `application` → `domain`. Ninguna capa conoce la que tiene encima.
* `common` no depende de `features` ni de `bootstrap`.
* Un contexto solo usa otro a través de sus casos de uso o de sus eventos.

WARNING: Estas reglas no se comprueban automáticamente. Está previsto un test de ArchUnit (link:{docs-root}/plan/TODO/issue-A3.1-archunit-reglas-arquitectura.md[A3.1]).

== Contextos y API

* La API se diseña primero en el contrato OpenAPI (`src/main/resources/META-INF/openapi/api.yaml`). `./mvnw generate-sources` genera las interfaces y los controladores las implementan. No se edita el código generado.
* Las rutas `/api/...` son las de la API de administración.
ifdef::module-oauth[]
* Las rutas `/oauth/...` son las del protocolo OIDC y las páginas de login.
endif::[]
* Cada contexto tiene su documentación técnica en `docs/technical/contexts/<contexto>`.
