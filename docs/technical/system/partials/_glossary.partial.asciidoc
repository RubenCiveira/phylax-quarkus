= Glosario

[glossary]
Actor:: Quien ejecuta una operación: usuario, cliente o sistema, con su tenant, scopes y roles. Va en el `OperationContext`.
Agregado:: Entidad de dominio con sus reglas, que registra los eventos de lo que le ocurre.
Caso de uso:: Operación de la aplicación sobre una entidad (`create`, `update`, `revoke`…). Es el puerto de entrada de la arquitectura hexagonal.
Campo fijo:: Campo que el actor no puede elegir porque se rellena con su contexto, como el tenant.
Campo oculto:: Campo que se elimina de la respuesta porque el actor no puede verlo.
Cursor:: Valores del último elemento leído, con los que se pide la página siguiente de un listado.
Gateway:: Puerto de salida declarado en `domain/gateway` e implementado por un adaptador en `infrastructure/driven`.
Generation Gap:: Separación entre el código que el generador sobrescribe (marcado `@autogenerated`) y el que mantiene el desarrollador.
Modelo:: Descripción XML de entidades, campos, relaciones y políticas a partir de la que se genera el código.
Pepper:: Secreto de servidor que se combina con un valor antes de calcular su huella HMAC. Un volcado de la base de datos no basta para comprobar los secretos.
Política:: Observador CDI escrito a mano que decide, valida o completa una operación sin tocar el código generado.
RBAC:: Control de acceso basado en roles. Decide si un actor puede ejecutar una acción sobre un recurso y qué campos ve.
ifdef::module-oauth[]
Relying party:: Aplicación que delega la autenticación en el servidor OIDC (cliente OAuth).
Resource server:: API que acepta los tokens del servidor OIDC y define sus propios roles.
endif::[]
Seed:: Datos iniciales que se cargan con la base de datos vacía (`migration/seed`).
Tenant:: Organización aislada, con sus usuarios, clientes y configuración propios.
Tenant raíz:: El tenant de la plataforma (`main`). Sus administradores, con el scope `platform:global_access`, gestionan todos los tenants.
Ventana de escrituras pendientes:: Tiempo tras una escritura durante el que las lecturas de esa entidad van al primario y no se cachean.
Visibilidad:: Reglas que limitan qué instancias y campos de una entidad ve cada actor.

ifdef::module-oauth[]
Los términos del protocolo (PKCE, PAR, DCR, ACR, DPoP, pairwise…) se explican en la xref:{docs-root}/functional/oauth/01-vision-general.adoc[visión general de OAuth].
endif::[]
